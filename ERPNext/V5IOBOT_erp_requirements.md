## 一、核心痛点

1. **背调数据分散** — 飞书背调库、本地 memory.md、completed_backd/ 归档文件、STATE.yaml 四处记录，无统一数据源
2. **背调流程无系统化** — 从接收线索→多源采集→交叉验证→信用评级→通知谈判官，全靠 Agent 手动串联，无工作流引擎
3. **客户画像碎片化** — 同一客户的信息散落在飞书记录、本地背调报告、Slack 对话、历史 session 中，无法一屏总览
4. **市场情报无结构化存储** — XCrawl 采集数据、竞品分析、行业动态以 JSON/Markdown 文件堆积，缺乏查询和趋势分析能力
5. **信用评级无标准模型** — S/A/B/C 评级依赖主观判断，缺乏量化评分体系和历史数据回溯
6. **与谈判官交接效率低** — 背调完成后通过文件+Slack通知，无自动化交接工作流和状态追踪

## 二、情报官 ERP 功能需求

### 2.1 背调管理模块（核心）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 背调任务队列 | 接收增长官/谈判官/总指挥的背调申请，自动创建任务，支持优先级（P0=4h/P1=24h/P2=48h） | 🔴 高 |
| 背调工作流引擎 | 标准化流程：接收→采集→验证→评级→输出→通知，每步状态可追踪 | 🔴 高 |
| 背调报告模板 | 标准化报告格式（基本信息/业务评估/决策链/信用评级/风险评估/结论），一键生成 | 🔴 高 |
| 背调时限监控 | 自动计算剩余时间，临近到期提醒，超时告警推送总指挥 | 🔴 高 |
| 背调历史检索 | 按客户名/国家/日期/评级检索历史背调记录，支持模糊搜索 | 🟡 中 |
| 批量背调 | 支持增长官批量移交线索（如 XCrawl 266家），自动分批处理 | 🟡 中 |
| 背调质量评分 | 背调完成后自评信息完整度（如：公司资质✓ 业务规模✓ 信用评级待补充） | 🟢 低 |

### 2.2 客户画像模块

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 客户360°视图 | 一页展示：公司基本信息 + 注册资质 + 业务规模 + 联系人 + 背调历史 + 信用评级 + 风险标签 | 🔴 高 |

### 2.3 信用评级模块

**IO 与其他 Agent 的数据流**：

| 上游 → IO | 数据 | 说明 |

| IO → 下游 | 数据 | 说明 |

## 七、技术建议

1. **ERPNext 客户模块扩展** — 在标准 Customer DocType 基础上扩展背调相关字段（信用评级、决策链、风险标签）
2. **自定义 Backcheck DocType** — 新建背调任务 DocType，包含状态机（待处理→采集中→验证中→已完成→已交接）
3. **工作流引擎** — 利用 ERPNext Workflow 实现背调流程自动化和状态流转
4. **定时任务** — 利用 ERPNext Scheduled Jobs 实现背调时限监控和日报自动生成
5. **Webhook 集成** — 背调完成通过 Webhook 触发 A2A 通知和飞书同步
6. **REST API 扩展** — 为 Agent 间通信提供标准 REST 接口
7. **数据看板** — 利用 ERPNext Dashboard 实现背调质量仪表盘和市场情报可视化
8. **全文搜索** — 利用 ERPNext 全文检索能力，支持客户/背调报告的模糊搜索
