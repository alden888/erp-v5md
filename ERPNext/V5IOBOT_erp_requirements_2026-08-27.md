**角色**: 情报官 — 客户背调 / 市场情报 / CRM 维护

## 一、当前痛点（手动/低效流程）

| # | 痛点 | 严重程度 | 说明 |
|---|------|----------|------|
| 1 | **背调数据四处散落** | 🔴 致命 | 飞书背调库、本地 memory.md、completed_backd/ 归档、STATE.yaml 四处记录，无统一数据源 |
| 2 | **背调流程无系统化** | 🔴 致命 | 接收线索→多源采集→交叉验证→信用评级→通知谈判官，全靠 Agent 手动串联，无工作流引擎 |
| 3 | **客户画像碎片化** | 🔴 高 | 同一客户信息散落在飞书记录、本地背调报告、Slack 对话、历史 session 中，无法一屏总览 |
| 4 | **市场情报无结构化存储** | 🟡 中 | XCrawl 采集数据、竞品分析、行业动态以 JSON/Markdown 文件堆积，缺乏查询和趋势分析能力 |
| 5 | **信用评级无标准模型** | 🔴 高 | S/A/B/C 评级依赖主观判断，缺乏量化评分体系和历史数据回溯 |
| 6 | **与谈判官交接效率低** | 🔴 高 | 背调完成后通过文件+Slack通知，无自动化交接工作流和状态追踪 |

**具体场景**:
- **场景A**: CEO问"某客户背调做了吗"→ 需要翻飞书+本地文件+Slack才能回答
- **场景B**: 谈判官问"客户X的决策人是谁"→ 背调报告在某个文件夹里，手动查找
- **场景C**: 增长官移交266家XCrawl线索→ 无批量导入机制，逐条手动处理
- **场景D**: 背调完成48h后谈判官仍未联络→ 无超时预警机制

## 二、核心功能需求（P0/P1/P2排序）

### 2.1 背调管理模块（核心 — P0）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 背调任务队列 | 🔴 P0 | 接收 GO/NO/CMD 的背调申请，自动创建任务，支持优先级（P0=4h / P1=24h / P2=48h） |
| 背调工作流引擎 | 🔴 P0 | 标准化流程：接收→采集→验证→评级→输出→通知，每步状态可追踪 |
| 背调报告模板 | 🔴 P0 | 标准化报告格式（基本信息/业务评估/决策链/信用评级/风险评估/结论），一键生成 |
| 背调时限监控 | 🔴 P0 | 自动计算剩余时间，临近到期提醒，超时告警推送总指挥 |
| 飞书Base自动同步 | 🔴 P0 | 背调完成后自动同步到飞书背调库（tbl1scQOWNd9EhIh），状态更新为"已核实" |
| 背调历史检索 | 🟡 P1 | 按客户名/国家/日期/评级检索历史背调记录，支持模糊搜索 |
| 批量背调 | 🟡 P1 | 支持增长官批量移交线索（如 XCrawl 266家），自动分批处理 |

### 2.2 信用评级系统（P0）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 量化评分模型 | 🔴 P0 | 多维度自动计算：公司规模(20%) + 注册年限(15%) + 行业口碑(20%) + 财务状况(25%) + 合规记录(20%) |
| S/A/B/C 自动分级 | 🔴 P0 | S≥90 / A≥75 / B≥60 / C<60，自动映射 |
| 黑名单管理 | 🔴 P0 | 制裁名单/欺诈记录/严重违约客户自动标记为C级或禁入 |
| 评级历史追踪 | 🟡 P1 | 记录每次评级变化及原因，支持升降级追溯 |
| 评级校准机制 | 🟡 P1 | 结合实际交易数据（付款及时率、订单金额）回溯校准评级准确度 |

### 2.3 客户画像模块（P0）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 客户360°视图 | 🔴 P0 | 一页展示：公司基本信息 + 注册资质 + 业务规模 + 联系人 + 背调历史 + 信用评级 + 风险标签 |
| 决策链图谱 | 🔴 P0 | 可视化展示客户组织架构，标注关键决策人/采购负责人/技术联系人 |
| 客户标签系统 | 🟡 P1 | 多维标签：国家类型（火土/金水）、客户等级（S/A/B/C）、行业、采购偏好 |
| 客户生命周期 | 🟡 P1 | 线索→背调中→已核实→首次下单→复购→流失 全生命周期追踪 |

### 2.4 合规风险筛查（P0）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 金水型国家拦截 | 🔴 P0 | 英/法/日/韩/俄/加/北欧自动拦截并告警 |
| 火土型国家优先 | 🔴 P0 | 东南亚/中东/拉美/非洲优先推荐 |
| 禁区标记 | 🔴 P0 | 印度/巴基斯坦/孟加拉标记禁区 |
| 风险预警推送 | 🔴 P0 | 发现高风险信号自动通知 @V5RCBOT 和 @V5CMDBOT |

### 2.5 市场情报模块（P1）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 竞品数据库 | 🟡 P1 | 结构化存储竞品信息：产品线/价格/渠道/市场份额/动态更新 |
| XCrawl 数据集成 | 🔴 P0 | 自动导入 XCrawl 采集结果，去重、清洗、入库 |
| 情报来源管理 | 🟡 P1 | 记录每条情报的来源（Trade Map/Volza/Snov.io/Google/LinkedIn）、采集时间、可信度 |
| 行业动态看板 | 🟡 P1 | 聚合东南亚六国医疗行业新闻、政策变化、展会信息 |

## 三、数据需求（读写 + Agent 依赖）

### 3.1 情报官需要读写的数据

| 数据实体 | 读/写 | 说明 |
|----------|-------|------|
| 背调任务 | 读写 | 创建/更新/完成背调任务，状态流转 |
| 客户画像 | 读写 | 创建/更新客户360°视图、标签、决策链 |
| 信用评级 | 读写 | 创建/更新 S/A/B/C 评级，记录评级历史 |
| 市场情报 | 读写 | 录入/查询竞品数据、行业动态 |
| 风险评估 | 读写 | 合规筛查结果、风险标签 |
| 订单数据 | 只读 | 用于信用评级校准（付款历史、订单金额） |
| 供应商数据 | 只读 | 用于交叉验证客户资质 |
| 制裁名单 | 只读 | 来自RC风控官，用于合规筛查 |

### 3.2 与其他 Agent 的数据依赖

**IO 接收的数据**:

| 来源 Agent | 数据 | 触发场景 |
|-----------|------|----------|
| GO 增长官 | 客户线索（公司名/国家/联系方式/来源） | 新线索移交背调 |
| NO 谈判官 | 背调申请（客户名/紧急程度/关注点） | 谈判前需要客户核实 |
| CMD 总指挥 | 背调指令（P0/P1/P2优先级） | 紧急背调任务 |
| RC 风控官 | 制裁名单/禁入清单/合规更新 | 合规筛查数据源 |
| SC 供应链官 | 供应商资质数据 | 交叉验证 |

**IO 输出的数据**:

| 目标 Agent | 数据 | 触发场景 |
|-----------|------|----------|
| NO 谈判官 | 背调报告（信用评级+决策人+风险评估+联系方式） | 背调完成 |
| RC 风控官 | 风险信号（可疑客户/异常行为/合规风险） | 发现风险 |
| CMD 总指挥 | 情报摘要（市场发现/体系预警/背调进度） | 重大发现/日报 |
| GO 增长官 | 线索质量反馈（背调结果/建议分级） | 背调完成 |
| CO 现金流官 | 客户信用评级 | 用于账期决策 |

## 四、自动化期望

| # | 自动化场景 | 当前方式 | 期望方式 |
|---|-----------|----------|----------|
| 1 | **背调任务创建** | 手动接收线索，手动创建任务文件 | GO/NO通过ERP提交背调申请，自动创建任务并分配优先级 |
| 2 | **背调时限监控** | 无监控，靠记忆 | 自动倒计时，临近到期自动提醒，超时自动告警CMD |
| 3 | **背调完成通知** | 手动写文件+Slack通知Leo | 背调完成后自动通过A2A推送结构化报告给NO |
| 4 | **飞书同步** | 手动lark-cli命令行操作 | 背调完成后自动同步飞书背调库，字段映射可配置 |
| 5 | **合规筛查** | 手动检查客户国家是否合规 | 新客户录入时自动筛查国家类型，金水型/禁区自动拦截 |
| 6 | **信用评级** | 主观判断S/A/B/C | 基于量化模型自动计算评分并映射等级 |
| 7 | **日报生成** | 手动汇总当日背调情况 | 每日18:00自动生成背调日报并推送Slack |
| 8 | **批量线索处理** | 逐条手动处理XCrawl结果 | 支持批量导入，自动去重、清洗、创建背调任务 |
| 9 | **客户去重** | 无法识别重复客户 | 同一公司不同拼写/子公司的自动关联和去重 |
| 10 | **情报巡检** | 手动搜索行业新闻 | 定时自动扫描指定数据源，生成情报摘要 |

## 五、现有工具替代方案

| 当前工具/方式 | 问题 | ERP替代方案 |
|---------------|------|-------------|
| **飞书背调库**（tbl1scQOWNd9EhIh） | 仅做存储，无工作流 | ERP为主数据源，飞书为只读镜像（单向同步） |
| **memory.md** 本地归档 | 文件堆积，无法查询 | 情报记录结构化入库，支持全文搜索和筛选 |
| **completed_backd/** 文件夹 | 历史背调报告散落 | 背调报告作为ERP附件，关联到客户和任务 |
| **lark-cli** 命令行操作 | 手动执行，易出错 | ERP API自动调用飞书同步 |
| **Slack @mention** 通知 | 无状态追踪，容易遗漏 | ERP内建通知+A2A推送，带状态追踪 |
| **XCrawl JSON 文件** | 需手动解析和导入 | XCrawl结果自动导入ERP，结构化存储 |
| **Google/LinkedIn 手动搜索** | 无法批量，结果不结构化 | 采集结果直接录入ERP情报记录 |
| **信用评级主观判断** | 无量化标准 | 量化评分模型，自动计算+历史校准 |
