## 一、核心痛点

### 1.1 风控流程缺乏系统化支撑

| 痛点 | 严重程度 | 说明 |
|------|----------|------|
| **制裁名单筛查依赖手动** | 🔴 致命 | OFAC/UN/EU/中国外交部名单更新后，需手动逐条比对客户，效率低且易遗漏 |
| **风控裁定无结构化存储** | 🔴 致命 | 裁定书散落在聊天记录/本地文件，无法快速检索历史裁定，审计困难 |
| **CEO特批流程无电子留痕** | 🔴 致命 | 口头/聊天审批无法作为合规依据，一旦争议无法举证 |
| **客户准入与订单生命周期脱节** | 🟡 高 | 客户通过准入后，后续订单是否仍合规缺乏持续监控 |
| **背调→风控→谈判流程断裂** | 🟡 高 | 情报官背调结果→风控裁定→谈判官通知，依赖消息传递，易丢失 |
| **红线触发后处置无闭环** | 🟡 高 | 否决/暂停后缺乏系统化的跟进、到期提醒、自动失效机制 |

### 1.2 具体场景

1. **场景A**: 新客户来了，我需要手动查OFAC网站+UN名单+EU名单→比对客户名/股东/董事→耗时30分钟以上，且无法保证名单是最新版
2. **场景B**: CEO问"这个客户上次风控裁定是什么"→ 我需要翻聊天记录/本地文件才能回答
3. **场景C**: 某客户被🟡暂停，CEO说"我批了"但没书面记录→ 我无法放行，但业务方认为我在刁难
4. **场景D**: 已🔴否决的客户，3个月后另一Agent又提交同一客户→ 我没有自动提醒
5. **场景E**: 制裁名单更新了，新增某实体→ 我需要手动检查所有在途订单是否涉及该实体

## 二、功能需求

### 2.1 制裁名单自动筛查引擎 (P0 — 必须有)

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **名单自动导入** | P0 | 系统自动抓取OFAC/UN/EU/中国外交部最新制裁名单，每日更新 |
| **客户自动比对** | P0 | 客户准入时自动比对所有制裁名单，输出匹配度评分 |
| **关联方穿透筛查** | P0 | 不仅查客户本体，还需查股东/董事/受益所有人（需情报官提供关联方数据） |
| **在途订单批量扫描** | P0 | 名单更新后自动扫描所有在途订单，发现匹配立即🔴冻结并告警 |
| **匹配结果人工复核** | P0 | 系统比对结果需风控官人工确认，避免误判（同名不同人） |
| **筛查记录永久保存** | P0 | 每次筛查的时间/名单版本/结果/裁定不可删除 |

### 2.2 客户风控档案中心 (P0 — 必须有)

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **客户风控档案** | P0 | 每个客户一个风控档案，包含：背调报告、裁定书、制裁筛查记录、信用评级、历史违规 |
| **裁定书结构化存储** | P0 | 所有🔴否决/🟡暂停/🟢通过裁定结构化存储，支持按客户/日期/类型检索 |
| **信用评级管理** | P0 | A/B/C/D四级评级，D级自动禁止合作，评级变更需记录原因 |
| **客户状态实时监控** | P1 | 客户状态变更（如被制裁/被起诉）自动触发在途订单复查 |
| **黑名单永久标记** | P0 | 🔴否决的客户永久标记，任何Agent再次提交时自动告警 |

### 2.3 CEO特批电子流程 (P0 — 必须有)

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **特批申请单** | P0 | 标准化申请模板：业务必要性、风险缓释措施、限时要求 |
| **电子签字确认** | P0 | CEO通过飞书审批/电子签名确认，结果自动回写ERP |
| **特批记录永久保存** | P0 | 特批记录不可删除/修改，包含：申请人、审批人、时间、条件、有效期 |
| **特批到期自动失效** | P0 | 特批有有效期，到期自动恢复红线拦截 |
| **特批统计报表** | P1 | 统计特批频率、涉及客户、红线类型、趋势分析 |

### 2.4 一票否决执行引擎 (P0 — 必须有)

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **红线硬编码** | P0 | 预付款<30%/毛利率<40%/制裁名单/D级信用/制裁国家 → 系统自动拦截，非人工判断 |
| **否决自动通知** | P0 | 否决后自动通知相关Agent（CMD/NOBOT/COBOT），无需手动发送 |
| **否决原因结构化** | P0 | 否决原因标准化（红线类型+具体依据+法规引用），便于审计 |
| **强行执行告警** | P0 | 无特批强行执行被否决订单→系统自动告警到CEO+记录严重违规 |
| **否决案例月报** | P1 | 每月自动生成否决案例汇总，推送CEO |

### 2.5 合规审查工作台 (P1 — 重要)

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **待审队列** | P1 | 所有待风控审查的客户/订单集中展示，按紧急度排序 |
| **审查清单模板** | P1 | 制裁筛查/产品认证/合同条款/出口管制 → 标准化检查清单 |
| **审查对比视图** | P1 | 客户提交材料 vs 合规要求，差异高亮 |
| **审查意见批注** | P1 | 对合同条款逐条批注，标记风险条款 |
| **审查历史对比** | P2 | 同一客户/产品历史审查结果对比，发现异常变化 |

### 2.6 风控报表与趋势分析 (P1 — 重要)

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **风控日报自动生成** | P1 | 当日🔴否决/🟡暂停/🟢通过统计，自动推送CEO |
| **风控周报/月报** | P1 | 周/月维度风控趋势：否决率、特批率、高风险客户占比 |
| **风险类型分布** | P2 | 按红线类型/客户行业/目的国统计风险分布 |
| **合规健康度仪表盘** | P2 | 全公司合规健康度评分，CEO一屏总览 |

### 2.7 出口管制筛查 (P1 — 重要)

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **EAR/ITAR筛查** | P1 | 产品是否受美国EAR/ITAR管制，自动比对ECCN编码 |
| **中国出口管制法筛查** | P1 | 产品是否受中国出口管制，自动比对管制清单 |
| **目的国限制检查** | P0 | 自动检查目的国是否为制裁国家/地区（如伊朗、朝鲜等） |
| **最终用途审查** | P2 | 客户声明的最终用途是否合规（军用/核用等敏感用途告警） |

### 3.3 核心数据模型

```
客户风控档案(CustomerRiskProfile)
├── customer_id (PK)
├── customer_name (客户名称)
├── country (注册国家)
├── risk_rating: A|B|C|D (信用评级)
├── sanctions_check_status: 通过|匹配|待复核
├── sanctions_check_date (最近筛查日期)
├── sanctions_list_version (名单版本)
├── related_parties (关联方清单: 股东/董事/受益人)
├── blacklist_status: 正常|永久黑名单
├── credit_limit (信用额度)
├── payment_terms_limit (账期上限)
├── created_date (建档日期)
├── last_review_date (最近复核日期)
└── review_history (复核历史)

风控裁定(RiskDecision)
├── decision_id (PK)
├── customer_id (FK)
├── order_id (FK, nullable)
├── decision_type: 客户准入|订单合规|合同审查|供应商资质
├── decision_result: 🟢通过|🟡暂停|🔴否决
├── red_line_type: 预付款<30%|毛利率<40%|制裁名单|D级信用|制裁国家|资质缺失
├── decision_basis (裁定依据)
├── legal_reference (法规引用)
├── ceo_approval: 无需|待审批|已批准|已拒绝
├── ceo_approval_record (CEO特批记录)
├── ceo_approval_expiry (特批有效期)
├── decision_maker (裁定人: Clara Morgan)
├── decision_time (裁定时间)
├── expiry_date (裁定有效期)
└── audit_trail (操作日志，不可篡改)

合规审查单(ComplianceReview)
├── review_id (PK)
├── customer_id (FK)
├── order_id (FK, nullable)
├── review_type: 制裁筛查|产品认证|合同条款|出口管制
├── check_items (检查清单: 各项通过/未通过/需修改)
├── risk_findings (风险发现)
├── review_result (审查结论)
├── reviewer (审查人)
├── review_date (审查日期)
└── supporting_docs (支撑文件清单)
```

## 六、项目分期建议

## 七、验收标准

- [ ] 新客户准入时，系统自动完成OFAC/UN/EU制裁名单筛查，<5秒返回结果
- [ ] 制裁名单更新后，24小时内自动扫描所有在途订单，发现匹配立即🔴冻结
- [ ] 🔴否决的订单，无CEO特批记录时系统绝对无法放行
- [ ] CEO特批通过后，特批记录自动回写ERP，有效期到期自动恢复拦截
- [ ] 任一客户的风控裁定历史可在3秒内完整检索
- [ ] 黑名单客户被再次提交时，系统自动告警相关Agent
- [ ] 风控日报从ERP自动生成，无需手动拼接数据
- [ ] 所有风控操作记录不可篡改，永久保存

## 八、级列1权威声明

本需求文档中的所有P0功能均为级列1权威保障机制的核心组成部分。任何削弱风控能力的功能删减需CEO书面批准。

**底线原则**:
1. 制裁名单筛查不可降级 — 一次遗漏可能毁灭企业
2. CEO特批必须电子留痕 — 口头审批无效
3. 风控裁定不可篡改 — 审计追溯是合规生命线
4. 红线拦截必须硬编码 — 不可被绕过
