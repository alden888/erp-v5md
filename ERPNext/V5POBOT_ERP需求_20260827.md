## 一、核心业务场景

作为项目经理，我负责订单全生命周期管理、节点监控、跨Agent协调。当前痛点：
- 订单状态分散在飞书Base、本地文件、MEMORY.md，数据源不统一
- 节点预警依赖Cron定时任务，缺乏实时联动
- 跨Agent协调靠Slack/A2A，缺少统一工单流转
- 已结案订单反复出现在预警中，数据清理不及时

---

## 二、ERP功能需求

### 2.1 订单管理模块（核心）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 订单全生命周期跟踪 | P0 | PI→付款→生产→质检→物流→交付，每节点可追溯 |
| 订单状态自动流转 | P0 | 节点完成后自动更新状态，减少人工干预 |
| 订单归档/结案机制 | P0 | CEO确认结案后自动从在途列表移除，不再触发预警 |
| 订单关联文档 | P1 | PI、合同、质检报告、物流单号一键关联 |
| 订单复制/模板 | P2 | 同客户复购订单可快速复制历史模板 |

### 2.2 节点预警模块（核心）

| 功能 | 优先级 | 说明 |
|------|--------|------|
| T-3/T-1/T日三级预警 | P0 | 自动计算节点到期日，分级推送 |
| 预警升级机制 | P0 | 逾期>3天自动升级CEO，逾期>7天标红 |
| 预警责任归属 | P1 | 每个节点明确责任Agent，预警直达责任人 |
| 预警解除确认 | P1 | 风险消除后需责任人确认解除，避免误报 |

### 2.3 跨Agent协调模块

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 统一工单系统 | P0 | 协调请求生成工单，流转可追踪 |
| 工单SLA监控 | P1 | 超时未响应自动升级 |
| 工单关联订单 | P0 | 工单必须关联订单号，避免信息孤岛 |
| 协调记录归档 | P1 | 所有协调记录自动归档到订单详情 |

### 2.4 客户核实流程模块

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 新客户资质核查 | P0 | 背景核查→PI确认→支付凭证→出货确认→交付确认 |
| 核实流程阻断 | P0 | 核实未通过自动阻断订单推进 |
| 核实记录存档 | P1 | 核实凭证（营业执照、付款水单等）上传存档 |
| 黑名单管理 | P0 | RC裁定黑名单自动同步，全团可见 |

### 2.5 数据看板模块

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 在途订单看板 | P0 | 按状态/客户/交期分类展示 |
| 逾期订单看板 | P0 | 逾期天数、责任Agent、应对措施 |
| 订单进度日报 | P1 | 自动生成18:00日报，推送Slack/飞书 |
| CEO决策看板 | P1 | 毛利率、回款率、客户分布等关键指标 |

### 2.6 数据治理模块

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 数据源统一 | P0 | 飞书Base为唯一数据源，本地文件自动同步 |
| 已结案订单清理 | P0 | CEO确认结案后自动标记，不再出现在预警 |
| 数据一致性校验 | P1 | 定时校验飞书Base与本地文件一致性 |

## 五、技术建议

### 5.1 数据层
- **主数据源**: 飞书Base（已有，全团可访问）
- **本地缓存**: 各Agent本地STATE.yaml/MEMORY.md定时同步
- **数据同步**: Cron定时任务，每2小时全量同步一次

### 5.2 接口层
- **A2A协议**: 各Agent通过HTTP JSON-RPC读写ERP数据
- **Slack备用**: A2A超时30秒自动降级Slack @mention
- **飞书API**: lark-cli作为飞书Base操作工具

### 5.3 展示层
- **飞书仪表盘**: CEO/各Agent可在飞书直接查看
- **Web看板**: 可选搭建React前端（二期）
- **移动端**: 飞书App原生支持
