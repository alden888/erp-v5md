## 一、当前痛点（手动/低效流程）

### 1.1 线索数据孤岛问题

| 痛点 | 严重程度 | 说明 |
|------|----------|------|
| **线索数据四地分散** | 🔴 致命 | 飞书线索库(tbl6Ry4wO4SOfNn1)、本地memory目录、XCrawl采集结果、IO Inbox四个数据源，无法统一追踪 |
| **线索移交无闭环** | 🔴 致命 | 移交给IO背调后，背调完成/已核实状态需人工查询飞书，无法自动触发下一步 |
| **获客渠道ROI不可量化** | 🔴 致命 | LinkedIn/XCrawl/展会/社媒多渠道线索无法归因到成交，无法计算各渠道投入产出比 |
| **国家筛选规则硬编码** | 🟡 高 | CEO禁令国家分散在AGENTS.md和memory中，XCrawl脚本需手动维护过滤列表 |
| **查重机制碎片化** | 🟡 高 | deduplicate_leads.sh仅覆盖本地memory和IO Inbox，无法覆盖飞书/NO客户库全链路 |
| **客户等级标准不统一** | 🟡 高 | 历史数据中A1/A2/B/D/P0-P3多种标准混用，需人工映射到S/A/B/C |

### 1.2 具体场景

1. **场景A**: XCrawl采集了50条线索→手动写入memory→手动查重→手动写入飞书→手动生成IO背调文件→手动A2A通知IO，整个流程耗时2小时以上
2. **场景B**: CEO问"本月LinkedIn获客效果如何"→我需要手动统计LinkedIn来源线索数、背调通过率、成交率，无法实时回答
3. **场景C**: 某客户已在NO客户库中，但XCrawl再次采集到→没有自动查重→重复移交给IO背调→浪费IO资源
4. **场景D**: 背调已完成3天，但我不知道→没有自动提醒→线索积压在IO环节

## 二、核心需求（P0/P1/P2排序）

### 2.1 CRM 线索管理模块

| 功能 | 优先级 | 说明 |
|------|--------|------|
| **线索全生命周期状态机** | P0 | 采集→清洗→标记"潜在新客户"→移交IO背调→已核实→NO联络→成交，全程状态驱动，自动流转 |
| **线索360视图** | P0 | 一页展示：基本信息+来源渠道+国家/优先级+背调状态+订单历史+下次动作 |

| **客户分级管理** | P0 | S/A/B/C四级（年采购额>$500K/$100K-500K/$50K-100K/<$50K），支持自动升降级 |
| **国家筛选引擎** | P0 | 内置CEO禁令国家列表（孟加拉/印度/巴基斯坦/英法日韩/俄加北欧），采集时自动拦截并记录 |

| **标签系统** | P1 | 自定义标签：目标品类(GLP-1/PVC硬片/注射器)、市场属性(火土/金水)、温度(冷/温/热) |

## 八、技术建议

1. **ERPNext CRM模块为基础**：利用ERPNext自带的Lead/Opportunity模块扩展，减少自定义开发量
2. **Webhook驱动协同**：线索状态变更通过Webhook触发A2A通知IO/NO，替代现有手动A2A调用
3. **飞书Bitable双向同步**：通过ERPNext自定义脚本+飞书开放API实现双向数据同步，保持现有飞书工作流不变
4. **XCrawl作为外部数据源**：ERPNext通过Server Script定时调用XCrawl SERP API，结果自动入库
5. **国家筛选配置化**：将禁令国家列表从硬编码改为ERP配置表，CEO可直接在ERP中管理
