**整理依据**：10位Agent的18份原始需求文档 + Doubao统一基线v1.0 + 优化版v2.0 + CEO基础设置拍板（ERPNext底座/飞书仅展示/A/B机部署）
**整理目的**：供CEO(Alden)拍板、总指挥(Kellan)排期、各Agent对齐的最终基线

## §0 一句话结论

**决策点从6个增至7个，其中2项已拍板（数据权威源、技术选型），剩余5项待CEO确认后即可进开发排期。** v2.0的六块P0地基判断维持不变；本版补齐库存、采购订单、发票三大交易型模块，并落地A/B机部署架构（A机现金库=账本权威+安全优先，B机创收库=业务录入+进取迭代）。

## §1 待CEO/总指挥决策清单（7项，2已拍板 / 5待拍板）

### ✅ 已拍板

**分歧1：数据权威源**
`CEO台账（权威输入）→ ERP（系统唯一账本 Source of Truth）→ 飞书Base（仅作展示层，不承担记录）`。

**分歧7【新增·已拍板】：技术选型与部署**
- 底座：**ERPNext (Frappe)** 为系统账本 + 飞书Base仅展示层
- 部署目标：**A机与B机**（A机=主节点账本权威，B机=从节点业务录入，见§5）
- VPS1/VPS2 不承载ERP核心数据（详见§5）

### ⏳ 待拍板

**分歧2：信用评级体系** — 建议双维度拆分（商机潜力S/A/B/C by GO/NO；信用风控A/B/C/D+黑名单 by IO/RC/CO），避免字母撞车（IO的C=风险 vs GO的C=小客户）。

**分歧3：毛利率红线口径** — 建议 ≥40%通过 / 35-40%CEO审批 / <35%书面特批（一票否决+记录），叠加SC分品类优秀线（多肽>60/包装>50）作预警。

**分歧4：订单状态机** — 建议统一10节点：`线索→背调→报价→合同→预付款→生产→质检→发货→尾款→结案`。

**分歧5：IO背调时限口径** — 建议以客户等级为基础（S=24h/A=48h/B=72h/C=96h），叠加任务紧急标记压缩（CMD/CEO直接下达按P0=4h执行）。

**分歧6：RX/GO职责边界** — 建议RX负责外部数据源挖掘+初步过滤（产出原始线索，状态机首节点写入权归RX）；GO负责清洗+深度标记+移交IO+渠道ROI/漏斗运营，不重复采集。

## §3 订单核心数据模型

```
订单 Order
├── order_id (PK, 格式: V5M+YYMM+DD+XX，如V5M260720A3)
├── customer_id (FK)
├── status: 线索|背调|报价|合同|预付款|生产|质检|发货|尾款|结案
├── quotation_amount        (报价金额)
├── cost_amount             (成本金额，SC核算)
├── reviewed_cost           (复核后成本，CO确认)
├── gross_margin_pct        (毛利率，自动计算)
├── prepayment_pct          (预付款比例)
├── prepayment_amount       (预付款金额)
├── balance_amount          (尾款金额)
├── payment_terms_days      (账期天数)
├── invoice_date            (开票日期)
├── ship_date               (发货日期)
├── prepayment_received_date
├── balance_due_date
├── balance_received_date
├── closed_date / closed_reason
├── red_line_flags          (红线标记数组)
├── cost_review_status: 待复核|已复核|已确认
├── risk_ruling: 🟢通过|🟡暂停|🔴否决
├── ceo_exception_id (FK)   (关联CEO特批记录，含有效期)
├── po_ref (FK)             【新增】关联采购订单(成品销售→原料采购追溯)
└── invoice_id (FK)         【新增】关联发票记录(开票→寄送→签收状态)
```

## §4 跨模块统一规范

### 4.1 通知降级链路
`A2A(HTTP JSON-RPC) 优先 → 超时30秒自动降级Slack @mention → 关键节点(结案/L3警报/风控否决)同步Telegram推CEO → 全部动作同步飞书展示层`

### 4.2 跨Agent核心数据流矩阵

| 流向 | 数据 | 触发场景 |
|------|------|----------|
| RX→GO | 原始线索(公司/国家/联系人/来源) | 挖掘完成 |
| GO→IO | 标记线索 + 移交文件 | 深度标记完成 |
| IO→NO | 背调完成通知 + 已核实客户 | 背调通过 |
| IO→RC | 制裁/合规风险情报 | 发现高风险信号 |
| NO→PO/CO | 订单号/PI金额/付款条款/交期承诺 | 订单创建 |
| SC→CO | 成本明细/BOM/供应商报价 | 核价完成 |
| SC→PO | 采购到货/生产完成/质检报告/物流单号 | 节点完成【新增】 |
| CO→RC | 客户回款历史/逾期记录 | 风险评估 |
| RC→NO/CMD/CO | 裁定结果🟢🟡🔴 + 黑名单 | 裁决完成（乱码已修） |
| PO→CMD | 逾期清单/T-3/T-1告警/进度日报 | 每日18:00 |

### 4.3 外部数据集成清单

| 数据源 | 用途 | 需求方 | 优先级 |

| OFAC/UN/EU/中国外交部制裁名单 | 客户/在途订单合规筛查 | RC | P0 |

### 4.4 权限与非功能需求（含RC硬指标）

| 类别 | 要求 |
|------|------|
| 角色权限隔离 | CEO全量可见；总指挥全量读+任务分配；各Agent读写自身模块，只读全局展示数据 |
| 敏感字段加密 | 毛利率、预付款金额、银行账号等财务敏感字段加密存储 |
| 并发写入策略 | 多Agent同时写入以乐观锁处理，最后写入为准并记录冲突日志 |
| 响应时间 | 查询<2秒，写入<5秒 |
| 制裁筛查响应【新增】 | 单客户筛查<5秒返回结果（RC，P0） |
| 制裁名单同步延迟【新增】 | 名单更新后<24小时内同步并触发在途订单复查（RC，P0） |
| 可用性 | 7×24，A/B机主从，故障自动切换 |
| 审计追溯 | 所有操作只追加(append-only)，不可删除/修改 |
