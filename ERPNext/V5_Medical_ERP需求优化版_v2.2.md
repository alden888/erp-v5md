## §1 决策清单（7项：6已拍板 / 1待确认）

### ✅ 已拍板

**分歧1：数据权威源**
`CEO台账（权威输入）→ ERP（系统唯一账本 Source of Truth）→ 飞书Base（仅展示层，不承担记录）`。

**分歧2：信用评级 —— 统一标准 S/A/B/C，双维度拆分**【CEO v2.2拍板】
> 全公司统一用 **S/A/B/C** 一个字母标准，但分**两个独立维度**存在客户档案里，互不混淆：

| 维度 | 口径方 | S | A | B | C |
|------|--------|---|---|---|---|
| **商机潜力** | GO/NO（年采购额+采购潜力） | ≥$500K | $100-500K | $50-100K | <$50K |
| **信用/风控** | IO量化评分 + RC裁定 + CO回款校准 | ≥90分 | ≥75分 | ≥60分 | <60分 |

- 两维度是**两个独立字段**：一个客户可以"潜力S + 信用B"。
- **信用C级 = 默认禁入**（替代原RC的D级），特殊情况需RC裁定+CEO特批。
- **黑名单 = 永久禁入，无例外**，任何Agent再次提交自动告警。

**分歧3：毛利率口径 —— 四档新口径**【CEO v2.2拍板】
| 档位 | 阈值 | 系统行为 |
|------|------|----------|
| 🟢 优秀 | ≥40% | 绿灯，正常报价，无需审批 |
| 🟢 通过 | 35%-40% | 绿灯，正常通过（原"35-40需CEO审批"规则被CEO本次决策取代） |
| 🟡 特批 | <35% | 需CEO审批解锁，留痕 |
| 🔴 特批·默认拒绝 | <20% | 仅CEO书面特批+一票否决永久记录（近似硬底线） |

- 分品类优秀线（多肽>60%/包装>50%，SC提供）仅作**预警参考**，不作拦截。
- 生效说明：NO原文档"35-40%需CEO审批 / <35%拒绝"已按CEO决策更新为上述四档。

**分歧5：IO背调时限 —— 三档任务时限**【CEO v2.2拍板】
| 任务类型 | 完成时限 |
|----------|----------|
| 紧急任务 | **1-4小时**内完成 |
| 一般任务 | **4-8小时**内完成 |
| 积压任务 | **8-12小时**内完成 |

- 取代原"优先级P0=4h/P1=24h/P2=48h"与"客户等级S=24h/A=48h/B=72h"两套口径。
- 紧急任务定义由CMD/CEO/谈判官标注"紧急"标记触发；超时自动告警推送总指挥。

**分歧6：RX/GO职责边界 —— 角色重定位**【CEO v2.2拍板】
- **RX = 开发官（Rex）**：市场研究与**开发产品方向**——外部数据源挖掘（LinkedIn/海关数据ImportGenius/Panjiva/Google Maps/展会名录）、目标市场/行业研究、新品类与产品方向探索，产出"原始线索 + 市场/产品方向情报"。
- **GO = 增长官（Mia）**：**业务增长方向**——线索清洗+深度标记、移交IO背调、全渠道ROI/获客漏斗/社媒运营。
- 边界：**采集与市场研究归RX**，GO不重复采集；状态机首节点"线索"写入权归RX，GO在其基础上流转状态（配合全链路查重防重复）。

**分歧7：技术选型与部署**
- 底座：**ERPNext (Frappe)** + 飞书Base仅展示层；部署 **A机主节点/B机从节点**（详见§5）。

### ⏳ 待确认

**分歧4：订单状态机（10节点）** —— 大白话解释见下，确认节点后冻结。

> **什么是订单状态机？** 订单就像快递包裹，从下单到签收要经过一系列"站点"（节点）。状态机=给订单规定一条固定转运路线，系统强制按顺序经过，每到一个站点状态自动更新。因PO/NO/CO三份文档各自画了不同路线（PO: PI→付款→生产→质检→物流→交付；NO: PI发送→预付款→生产→发货→尾款→完结；CO: 创建→报价→签约→生产→发货→回款→结案），导致同一订单在PO显示"生产中"、在CO显示"签约"对不上账。统一后任何订单任何时刻只有一个状态。
>
> **建议统一路线（10节点）**，每站标责任与预警：
> ```
> GO/IO    IO      NO/CO    NO/RC   CO/RC    PO/SC    SC     PO      CO/NO    CMD/CEO
> 线索 ──► 背调 ──► 报价 ──► 合同 ──► 预付款 ──► 生产 ──► 质检 ──► 发货 ──► 尾款 ──► 结案
> ```
> 每节点含：责任Agent / 进入条件 / 到期日 / 预警(T-3/T-1/T日)。节点可按实际业务增删（如"质检"并入"生产"、加"样品确认"）。

## §3 订单核心数据模型

```
订单 Order
├── order_id (PK, 格式: V5M+YYMM+DD+XX，如V5M260720A3)
├── customer_id (FK)
├── status: 线索|背调|报价|合同|预付款|生产|质检|发货|尾款|结案
├── quotation_amount / cost_amount / reviewed_cost
├── gross_margin_pct        (毛利率，按分歧3四档自动判定)
├── prepayment_pct / prepayment_amount / balance_amount
├── payment_terms_days / invoice_date / ship_date
├── prepayment_received_date / balance_due_date / balance_received_date
├── closed_date / closed_reason
├── red_line_flags          (红线标记数组)
├── cost_review_status: 待复核|已复核|已确认
├── risk_ruling: 🟢通过|🟡暂停|🔴否决
├── potential_grade: S|A|B|C   【新增，商机潜力维度】
├── credit_grade: S|A|B|C      【新增，信用风控维度】
├── ceo_exception_id (FK)      (关联CEO特批记录，含有效期)
├── po_ref (FK)                (关联采购订单)
└── invoice_id (FK)            (关联发票记录)
```
